# LibraMAS 智慧图书馆交互大屏实施说明

日期：2026-08-14  
基线：`codex/g1-runnable-skeleton` / `e1f046b`  
数据集与图谱版本：`lib-books-v1-20260810`

## 1. 本次实际产出

本次重构将原运行验收控制台升级为读者可直接使用的智慧图书馆交互大屏，同时保留旧组件、同步推荐 API 和默认 fail-closed 组合根。

前端新增五个独立路由：

- `/`：探索首页，提供自然语言入口、主题入口、实时馆藏数字、分类图和知识星图。
- `/recommend`：智能推荐与 8 Agent 协同舞台。
- `/graph`：有界知识图谱搜索与一跳展开。
- `/path`：入门、进阶、深化三阶段阅读路径。
- `/insights`：分类、年代、可用状态、热门主题和推荐通道贡献。
- `/system`：旧运行状态能力的兼容入口。

大屏 Shell 包括 88px 触控导航、顶部会话区、全局图书详情抽屉、系统状态抽屉和 120 秒访客会话重置。访客反馈仅保存在当前 Pinia 会话；演示画像必须由用户主动切换，并且只有后端 `interaction_pipeline=UP` 时才可发送真实反馈。

## 2. 新增公开只读接口

显式研究组合根新增 Exploration bounded context：

- `GET /api/v1/explore/overview`
- `GET /api/v1/explore/resources/{resource_id}`
- `GET /api/v1/explore/graph/search?q=...&limit=30`
- `GET /api/v1/explore/graph/nodes/{entity_id}/neighbors?limit=40`

馆藏概览采用 300 秒进程内缓存。MySQL 查询在完成后显式回滚；Neo4j adapter 仅包含常量、参数化 `MATCH` 查询，固定图谱版本，公开 Label、Relationship 和属性均使用白名单。公共图谱响应最多 60 节点、120 边，超限明确标记 `truncated`，不公开 SourceFile、SourceRecord、来源指纹或任意 Cypher 能力。

2026-08-14 本地纯 GET 验收读到：

- 馆藏资源 14,989 项，其中图书 14,986 册、论文 3 篇。
- 标签 8,522 个。
- 公开图谱节点 47,773 个、关系 130,192 条。
- “人工智能”局部图返回 24 节点、22 条边，包含 Book、Topic、Author、Publisher、Category、Keyword、SubjectCode。
- 图书节点成功映射 MySQL `resource_id`，详情接口返回真实题名、年份、状态和馆藏信息。

以上验收没有调用业务 POST，数据库写入为 0。

## 3. 异步推荐与真实 Agent 事件

研究运行时新增：

- `POST /api/v1/recommendation-runs`
- `POST /api/v1/recommendation-runs/{task_id}/clarifications`
- `GET /api/v1/recommendation-runs/{task_id}`
- `GET /api/v1/recommendation-runs/{task_id}/events?context_version=...`

Orchestrator 通过可选 `AgentProgressSink` 在真实状态转换和 Agent dispatch 前后发布经过过滤的事件。事件不包含 Prompt、模型原文、密钥、SQL 或数据库内部字段。

内存 Broker 的硬边界：

- 最多并发 8 个运行任务。
- 每任务最多 256 个事件。
- 终态保留 10 分钟。
- SSE 每 15 秒 heartbeat。
- 支持 `Last-Event-ID` 断线续传和身份隔离。
- 服务重启不会伪造恢复；前端会显示失败并允许使用相同幂等请求安全重试。

前端使用可附加身份 Header 的 Fetch SSE，不使用原生 EventSource。8 个角色固定为 IntentUnderstanding、UserProfile、ResourceSemantic、RecommendationPolicy、CandidateRecall、Ranking、Explanation 和 FeedbackLearning；界面状态只由真实事件驱动。

## 4. 推荐结果与交互边界

公开推荐项新增裁剪后的多通道证据：综合分数、通道、通道分数、通道排名、主召回通道、证据引用和负反馈惩罚。阅读路径优先按真实难度 1–2、3、4 分为三个阶段；缺少难度时按稳定排名三等分，不使用随机分组。

图书无可靠封面时由题名稳定哈希生成程序化封面，不访问外部图片服务。

曝光记录必须同时满足：

1. 用户主动切换演示画像；
2. 后端 readiness 明确返回交互管线 UP；
3. 当前图书来自真实推荐项；
4. 详情持续可见至少 1 秒。

页面加载本身不会产生曝光。访客模式下喜欢、借阅意向和不感兴趣只留在浏览器内存，会话重置时清空；重置不会删除任何后端事实。

## 5. 视觉与运行验收

已通过浏览器真实页面检查：

- 1920×1080：首页关键内容无需整页滚动，Agent 舞台、知识图谱和洞察图表正常渲染。
- 3840×2160：页面宽高无溢出，触控导航高度 96px，搜索框高度 110px。
- 1366×768：搜索、主题、实时数字和主操作均在首屏，页面宽高无溢出。
- 390×844：降级为底部导航，页面无横向溢出，五个导航触控区均为 72×56px。
- 浏览器控制台无 error 或 warning。

前端使用 Vue Router、Pinia 和 ECharts 6；ECharts 仅按需注册 Graph、Pie、Sunburst、Bar、Scatter 和 Radar，不引入第二套图表框架。路由采用动态导入，主包约 145 KB，ECharts 图表包约 604 KB（均为压缩前构建尺寸）。

## 6. 安全状态与后续真实验收

本次没有删除文件、数据库记录、容器或数据卷，没有运行数据库删除语句，也没有执行真实推荐/反馈 POST。旧前端组件仍在原路径，旧同步 API 保持挂载。

当前研究运行时 readiness 已显示 MySQL、Neo4j、Chroma、推荐链路、交互管线和 DeepSeek `deepseek-v4-flash` 为 UP。这证明真实 LLM 已配置并通过 readiness；但新的异步推荐全场景 POST 验收仍须单独生成精确 ChangePlan，至少列明：

- 测试用户、session UUID、request UUID 和幂等键。
- 预计 MySQL 追加行数及涉及表。
- DeepSeek 最大请求次数与 token 上限。
- 是否包含澄清、反馈和 Outbox Worker。
- `plan_id`、`plan_hash`、执行命令和回滚边界。

只有用户再次精确批准该 ChangePlan 后，才能执行真实推荐、曝光、反馈或画像投影验收。
