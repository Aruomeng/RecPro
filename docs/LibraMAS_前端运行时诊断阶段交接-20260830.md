## 阶段目标

将后端 `GET /api/v1/debug/runtime` 接入现有系统状态抽屉和兼容页，让研究管理员可以查看显式组合根的生命周期与连接池公开指标。读者首页、访客会话和普通账号不会请求或看到该接口。

## 实际产出

- 新增 `frontend/src/domain/runtimeDiagnostics.ts`：冻结 `runtime-diagnostics-v1` 类型与严格解码器，限制资源数量、资源类型、指标键和有限数值。
- 新增 `frontend/src/api/runtimeDiagnosticsClient.ts`：使用正式 Bearer Token 的只读 GET 客户端，包含 JSON、错误、超时和取消边界。
- 新增 `frontend/src/components/RuntimeDiagnostics.vue`：在状态抽屉中展示资源快照、生命周期、采集时间、池容量、租约和获取耗时；所有指标使用中文标签和单位，不显示凭据或业务数据。
- `frontend/src/stores/system.ts` 根据 `research.audit.read` 权限管理运行时诊断状态；访客/普通用户始终保持 `idle`，登出后立即清空本地快照。
- `App.vue` 与 `SystemView.vue` 复用同一系统状态组件；登录、权限变化后才发起读取，刷新按钮仅重复只读 GET。
- `styles-v2/components.css` 增加响应式蓝白诊断卡片，桌面、窄屏和移动端均保留可读字号与触控尺寸。

## 安全与兼容边界

- 后端路由仍受 Debug API 显式开关控制，默认 health-only 应用不挂载。
- 前端不发送 `X-Demo-User-Id` 访问诊断接口；仅在正式认证且具有 `research.audit.read` 时发送 `Authorization: Bearer`。
- 后端与前端均采用白名单指标，未知字段、嵌套对象、敏感字符串、非有限浮点数和超界数量都会被拒绝或丢弃。
- 诊断加载失败只影响状态展示，不阻断馆藏、图谱、推荐或 Agent Workspace。
- 没有新增业务写接口，不触发数据库、Neo4j、Chroma、审计、画像或 DeepSeek 操作。
