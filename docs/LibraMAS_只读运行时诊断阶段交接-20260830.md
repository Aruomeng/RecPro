```text
交接ID：RUNTIME-DIAGNOSTICS-20260830-001
Gate：显式 Debug 开关 / research_admin Bearer / 运行时指标安全投影
状态：CODE_COMPLETE / NO_WRITE_VALIDATION_PASS
时间：2026-08-30（Asia/Shanghai）
```

## 阶段目标与安全边界

本阶段把上一阶段显式组合根注册的运行时资源指标接到一个只读运维边界，便于研究管理员判断连接池和资源生命周期状态。诊断接口不参与推荐、画像、反馈、图谱或审计写入，也不创建新的运行时资源。

接口只在 `debug_api_enabled=true` 且推荐 API 被显式组合时挂载：

```text
GET /api/v1/debug/runtime
Authorization: Bearer <verified research_admin token>
```

默认模块级应用仍为 health-only，因此默认实例访问该路径返回 404。即使 Debug API 被显式挂载，也必须通过注入的 Bearer Resolver 并拥有 `research_admin` 角色；`X-Demo-User-Id` 永远不能作为诊断凭据，普通 `user` 也会被拒绝。

## 实际产出

- `backend/app/api/auth.py` 新增统一的 `require_research_admin_principal`，让 Debug 端点共用正式 Bearer、演示身份拒绝和角色校验。
- `backend/app/platform/lifecycle.py` 新增 `RuntimeResourceRegistry.diagnostics_snapshot()`，返回注册表关闭状态和显式资源快照；不隐式发现或关闭外部资源。
- `backend/app/api/debug.py` 新增 `/api/v1/debug/runtime`，将运行时资源指标转换为 `runtime-diagnostics-v1`。
- `backend/app/api/models.py` 新增严格的 `RuntimeDiagnosticsResponse` 和 `RuntimeMetricResourceResponse`。
- `backend/app/main.py` 仅向已挂载的 opt-in Debug Router 注入 `resource_registry.diagnostics_snapshot`。

## 公开数据投影

HTTP 层只允许连接池容量、租约、获取/释放计数和获取耗时等固定字段：

```text
initialized, closed, min_size, max_size, recycle_seconds,
acquire_timeout_seconds, pool_size, free_size, active_leases,
pending_acquires, acquire_count, acquire_timeout_count, release_count,
total_acquire_ms, last_acquire_ms, average_acquire_ms
```

任意未列入白名单的字符串、嵌套对象、凭据、连接选项和异常文本都会被丢弃；浮点非有限值也不会进入响应。资源类型限制为短 ASCII 标识，最多 64 个资源、每次最多读取 64 个快照。响应包含 `registry_closed`、`resource_count`、`collected_at` 和 `schema_version`，没有主机、用户名、密码、令牌、SQL、Cypher 或模型原文。

## 后续边界

本阶段只提供后端只读诊断契约。下一步如需将其展示在前端系统状态抽屉，应继续复用该响应模型和同一鉴权边界；不得把运行时诊断提升为公开访客接口，也不得通过诊断端点触发资源探测、推荐、画像或任何写操作。任何数据库迁移、真实账号/画像写入或新增 DeepSeek 请求仍需先生成并批准独立精确 ChangePlan。
