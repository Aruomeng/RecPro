# LibraMAS 合成研究基准使用说明

## 目的

当没有可用的真实读者行为、许可数据与人工标注时，项目可用本工具从已授权的本地馆藏元数据生成匿名、确定性、不可覆盖的合成研究基准，用于：

- 原型演示与端到端联调；
- 推荐、画像、反馈与降级链路的开发验证；
- `DEVELOPMENT_PROXY` 实验与消融机制检查；
- 前端大屏的数据展示与可用性验收。

它**不能**替代真实读者行为、知情同意、许可材料或双人盲标注；不得作为论文中“真实推荐准确率提升”“用户满意度提升”或统计显著性的确认性结论。

## 生成器与安全边界

生成器：[build_synthetic_research_benchmark.py](../scripts/build_synthetic_research_benchmark.py)

- 输入仅为本地 `Lib/` 书目元数据；不读取 MySQL、Neo4j、Chroma 或用户画像。
- 模拟用户 ID 为 `synthetic-u-xxxx`，不含真实身份信息。
- 事件、偏好和相关性标签均使用固定 seed 的元数据代理规则生成。
- 行为事件使用现有业务枚举：`VIEW_RESOURCE`、`FAVORITE_RESOURCE`、`BORROW_BOOK`、`NOT_INTERESTED`；未来接入时无需另造事件协议。
- 输出的 `manifest.json` 恒为 `classification=SYNTHETIC_DEVELOPMENT_ONLY` 与 `confirmation_eligible=false`。
- 输出目录必须是全新目录；同名目录不会覆盖。
- 数据库写入、DeepSeek 请求、删除操作均恒为 0。

## 与当前运行馆藏对齐的版本

若本地 `Lib/` 与当前 MySQL 的资源外部 ID 并非同一导入快照，应使用 `scripts/build_database_aligned_synthetic_benchmark.py`。它只读 `resource_catalog` 元数据，并将当前真实存在的 `resource_id/external_id` 固化到合成基准，避免后续演示行为引用不存在的书目。

本次已生成 `mysql-synthetic-research-20260901-001`：576 条当前馆藏资源、120 个模拟读者、1,920 条事件、120 个任务。随后的只读核验已确认，首个演示用户的 8 个资源均能唯一映射，16 个确定性事件 UUID 均不存在。

## 复现命令

```bash
PYTHONPATH=. .venv-g1-final-py311/bin/python scripts/build_synthetic_research_benchmark.py \
  --catalog-root Lib \
  --output artifacts/verification/synthetic-research/<新运行编号> \
  --dataset-version lib-synthetic-research-<版本> \
  --users 120 \
  --interactions-per-user 8 \
  --seed 20260901 \
  --write
```

改变 seed、用户数或交互数必须使用新的输出目录和数据集版本；历史产物不覆盖、不删除。

## 论文写作口径

可表述为：

> 本研究首先在基于馆藏主题、分类与中图法元数据构造的确定性合成基准上，验证了多智能体推荐原型的流程正确性、模块消融差异与故障降级能力。该基准不代表真实读者偏好，相关结果不用于推断实际推荐准确率或用户满意度。

若后续取得真实、脱敏且获许可的数据，仍须遵循 [正式论文实验材料交接清单](LibraMAS_正式论文实验材料交接清单-20260901.md) 重新冻结输入与运行确认性实验。

## 受控演示导入准备

`scripts/plan_synthetic_demo_behavior_import.py` 可从冻结基准为单个**既有研究演示用户**（仅 `1001` 或 `1002`）生成零写入行为导入意图。它只计划 `user_behavior_event` 追加，默认不创建画像 Outbox、不更新任何画像投影；不会使用真实登录账号。

实际导入前仍需单独 ChangePlan，固定事件 UUID、外部资源 ID 到 MySQL 资源 ID 的只读对账、目标用户、预期新增行数和回读条件。未经批准不得执行导入。

执行边界由 `scripts/build_synthetic_demo_behavior_change_plan.py` 与 `scripts/execute_synthetic_demo_behavior_change_plan.py` 固定：执行器只接受经批准且代码哈希一致的计划，只能向 `user_behavior_event` 追加 16 条固定 UUID 的合成事实；任何已存在 UUID、资源映射变化、目标账号变化、行数偏差或计划/代码哈希不匹配都会在提交前拒绝并回滚。它没有更新、删除、画像 Outbox、Neo4j、Chroma 或 DeepSeek 的执行能力。

首批导入已按批准计划完成；详细执行与回读结果见 [合成演示行为追加执行记录](LibraMAS_合成演示行为追加执行记录-20260901.md)。
