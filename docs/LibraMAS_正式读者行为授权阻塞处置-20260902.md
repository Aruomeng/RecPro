## 本阶段新增实现

- `scripts/build_formal_reader_behavior_consent_plan.py`：只读检查账号、角色、有效授权和全库计数，生成绑定当前 Git 提交的精确 ChangePlan。
- `scripts/execute_formal_reader_behavior_consent_plan.py`：只接受精确 `plan_id + plan_hash`，执行一次登录、一次 `BEHAVIOR_LEARNING=GRANT` 授权和一次退出；授权请求出现网络歧义时只做读取对账，绝不重试 POST。
- `Makefile` 增加 `build-formal-reader-consent-plan` 与 `execute-formal-reader-consent-plan`，将生成和执行边界固定化。
- 前端已有授权向导和状态提示；本阶段不替用户点击授权，也不自动发送业务反馈。

## 计划边界

计划只允许以下追加事实：

| 表 | 预计追加 |
|---|---:|
| `iam_auth_session` | 1 |
| `iam_refresh_token` | 1 |
| `iam_security_event` | 2（登录、退出） |
| `user_personalization_consent_fact` | 1（行为学习授权） |

账号授权版本、角色、画像、推荐、反馈、行为事件、Outbox、Agent Workspace、Neo4j、Chroma 和 DeepSeek 均不在计划内。执行器还会核对所有表计数，任何未列出的变化立即失败并保留现场。

文件删除、数据库物理删除、容器删除、数据卷删除和覆盖写入均为 `0`。一次性授权事实写入后不通过补偿删除回滚；若发生部分失败，必须生成新的前向 successor ChangePlan。

## 执行门禁

计划生成不会改变数据库。只有在用户明确批准生成结果中完全一致的 `plan_id` 和 `plan_hash` 后，才允许执行器建立写连接并调用身份 API。执行完成后再单独生成 G5 反馈/行为 Worker 的新基线与 successor ChangePlan；授权计划的批准不自动批准反馈写入或新增模型请求。

## 验证命令

```text
make build-formal-reader-consent-plan FORMAL_CONSENT_PLAN_RUN_ID=<new-run-id>
make execute-formal-reader-consent-plan \
  FORMAL_CONSENT_PLAN=<plan-path> \
  FORMAL_CONSENT_PLAN_ID=<approved-plan-id> \
  FORMAL_CONSENT_PLAN_HASH=<approved-plan-hash>
```

上述命令不会删除任何历史事实；执行前必须保留全库计数、账号授权和受保护凭据文件权限证据。
