## 目标与边界

本阶段只收口运行时资源管理和诊断边界，不改变推荐、身份、图谱、反馈或审计业务契约。只有显式组合根传入的资源才会被注册；默认 `backend.app.main:app` 仍为 health-only，注册资源为空。

本阶段未执行数据库连接、迁移、业务 POST、Neo4j/Chroma 写入、DeepSeek 请求、容器/数据卷操作或删除动作。文件删除数量为 0，数据库物理删除数量为 0。

## 实际产出

- 新增 `backend/app/platform/lifecycle.py`：有界 `RuntimeResourceRegistry`，按逆序关闭、按对象身份去重、关闭幂等，并提供仅包含公开指标的快照入口。
- `create_app` 增加可选 `managed_resources` 和 FastAPI lifespan；资源不通过依赖图隐式发现，关闭失败会继续尝试其余资源并返回聚合错误。
- Demo、Production、Research G4 组合根将显式注入的服务、进度 Broker、Workspace Broker、身份和知识审核服务纳入生命周期边界；旧调用方式保持兼容。
- MySQL 连接池新增 `MySQLPoolSnapshot`：初始化/关闭状态、配置边界、池大小、空闲连接、活跃租约、等待获取数、获取成功/超时次数、释放次数、总/最近/平均获取耗时；快照不包含 host、用户名、密码或令牌。
- 推荐、反馈、身份、探索、知识审核、画像读取和两个 Worker 的应用/适配器增加可选 `close`/`runtime_metrics` 端口；没有生命周期能力的测试替身不会被强制关闭。
- 进度 Broker 在关闭前等待已接受任务，Workspace Broker 在关闭前等待已接受观察，避免进程退出时遗留半完成内存任务。
- 通过 `backend/app/profile/public.py` 恢复旧连接工厂调用形态，并让轻量测试 Cursor 在缺少 `fetchone` 时安全回退到有界 `fetchall`，消除上一阶段的 Profile Workspace 兼容回归。
